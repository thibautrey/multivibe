## Hermes distant — capacité MultiVibe avec bascule transparente

Un service local installé sur la machine du client devient son unique upstream
OpenAI-compatible : le bridge décide, à chaque tour, de servir depuis
`multivibe.pleiades.solutions` ou depuis l'API Nous Research du client. Ni le
modèle, ni les outils, ni la mémoire, ni les serveurs MCP d'Hermes ne changent —
seuls deux valeurs de `~/.hermes/.env` et un service d'arrière-plan.

Le bridge est fourni dans l'archive Host de votre plateforme, sous
`bin/multivibe-hermes-bridge` (Linux) ou
`MultiVibe Host.app/Contents/Resources/app/bin/multivibe-hermes-bridge` (macOS),
avec `install-hermes-bridge.sh` à côté.

### Ce que fait le bridge

- **Bascule avant le premier token uniquement.** Après, l'erreur remonte et
  Hermes rejoue le tour : jamais de rejeu vers Nous, donc jamais de double
  exécution d'outils ni de sortie dupliquée.
- **Sticky 10 minutes** : une conversation basculée reste sur Nous, parce que le
  cache de prompt est local à chaque côté.
- **Bascule seulement si un modèle de classe équivalente existe.** La
  correspondance est lue dans le catalogue public de Nous, jamais inventée : un
  modèle absent laisse le bridge en attente plutôt que de répondre avec autre
  chose.
- **`nous-first` pendant le pilote** : edge injoignable, `5xx` ou timeout avant
  le premier token → Nous. Aucune régression par rapport à l'existant.

### Limites d'admission

Quatre étages appliqués dans cet ordre : capacité physique mesurée, part juste
par application, grâce de session, puis priorité calendaire. La grâce de session
ne donne jamais de capacité au-delà de la part juste — elle décide seulement qui
attend à l'intérieur de cette part, ce qui empêche la grâce de devenir un
contournement. Les sessions déjà lancées pendant une période creuse continuent,
même si la charge monte ensuite : le préfill est déjà payé.

### Correctifs

- **Les clés d'enrôlement ne disparaissent plus.** Le fichier de comptes avait
  deux écrivains qui le réécrivaient chacun en totalité ; une clé émise pouvait
  être effacée en quelques secondes et l'appel suivant répondait
  `401 invalid_api_key`. Les deux écrivains partagent désormais un verrou
  inter-processus et relisent avant d'écrire.
- **`--edge <hôte>` conserve le `/v1`.** Sans le préfixe, chaque sonde
  d'admission recevait un `404` et le bridge servait toute la conversation depuis
  Nous alors que l'edge était sain.
- **Le token Cloudflare Access est persisté à l'enrôlement**, au lieu de servir
  uniquement à l'échange : sans lui, chaque inférence repartait anonyme et
  recevait un `302`.
- **Une clé enrôlée peut être révoquée.** `DELETE /admin/proxy-api-keys/:id`
  répondait `404` pour toute clé créée par l'enrôlement, alors qu'elle continuait
  d'authentifier : l'offboarding était impossible.
- **Une politique d'admission peut être supprimée.** Supprimer une clé laissait sa
  réservation de part active, et aucun endpoint ne supprimait la politique.
  `DELETE /admin/application-policies/:application` comble ce trou.
- **Un tour en file n'affirme plus que le modèle est absent.** En mode
  `edge-first`, une attente dans le budget répondait `503 no_equivalent_model` —
  faux, et de nature à envoyer chercher un bug de mapping inexistant. Il répond
  désormais `edge_queued` avec un `Retry-After` fondé sur la file réelle.

### Enrôlement

Le client n'édite plus son `.env` à la main : `configure --env` écrit le bloc
managé (en préservant tout le reste, en `0600`, de façon idempotente).

Le prompt d'enrôlement se génère :

```
npm run hermes:enrollment-prompt -- \
  --code mvenr_… --edge https://multivibe.pleiades.solutions \
  --model <LLM_MODEL du client> --access-id <id> \
  --access-secret-path <chemin sur la machine du client> --out prompt.md
```

Le secret Access n'est accepté que sous forme de **chemin** : il ne peut pas
voyager dans le prompt. Le rendu refuse d'émettre un document contenant encore un
placeholder, et écrit `0600` parce qu'il porte un code vivant.

Voir `docs/hermes-bridge-enrollment-prompt.md` et
`docs/hermes-bridge-cloudflare-access.md`.
