## 0.2.148 — publication pipeline fixes

0.2.147 could not be published: the workflow failed for three independent
causes, two of which are fixed here.

- **Windows packaging.** `Expand-Archive` under Windows PowerShell 5.1 calls a
  three-argument `ExtractToDirectory` overload that only exists on .NET Core; on
  .NET Framework it fails. Both the packager **and** the verifier used it, so no
  Windows archive could be produced or verified. They now call the two-argument
  overload.
- **Go 1.26.10** carried GO-2026-6859 (header race in `net/http`, reachable from
  the updater) and the `govulncheck` step makes publication fail. The pinned
  version moves to **1.26.11**.
- The macOS failure (`codesign`: "A timestamp was expected but was not found")
  was not a code defect but the Apple timestamp service being unreachable from
  the runner at that moment.

The functional content is the one described below.

## Remote Hermes — MultiVibe capacity with transparent failover

A local service installed on the customer's machine becomes its single
OpenAI-compatible upstream: the bridge decides, on every turn, whether to serve
from `host.example.invalid` or from the customer's Nous Research API. Neither
the model, nor the tools, nor the memory, nor Hermes' MCP servers change — only
two values in `~/.hermes/.env` and a background service.

The bridge ships in your platform's Host archive, under
`bin/multivibe-hermes-bridge` (Linux) or
`MultiVibe Host.app/Contents/Resources/app/bin/multivibe-hermes-bridge` (macOS),
with `install-hermes-bridge.sh` alongside.

### What the bridge does

- **Failover before the first token only.** After that, the error propagates and
  Hermes replays the turn: never a replay to Nous, hence never a double tool
  execution nor duplicated output.
- **Sticky for 10 minutes**: a conversation that failed over stays on Nous,
  because the prompt cache is local to each side.
- **Failover only when a model of equivalent class exists.** The mapping is read
  from Nous' public catalogue, never invented: a missing model leaves the bridge
  waiting rather than answering with something else.
- **`nous-first` during the pilot**: edge unreachable, `5xx` or timeout before
  the first token → Nous. No regression compared with the existing setup.

### Admission limits

Four tiers applied in this order: measured physical capacity, fair share per
application, session grace, then calendar priority. Session grace never grants
capacity beyond the fair share — it only decides who waits inside that share,
which prevents grace from becoming a bypass. Sessions already started during an
off-peak period continue, even if load rises afterwards: the prefill is already
paid for.

### Fixes

- **Enrollment keys no longer disappear.** The accounts file had two writers,
  each rewriting it in full; an issued key could be erased within seconds and
  the following call answered `401 invalid_api_key`. Both writers now share an
  inter-process lock and re-read before writing.
- **`--edge <host>` keeps the `/v1`.** Without the prefix, every admission probe
  received a `404` and the bridge served the whole conversation from Nous while
  the edge was healthy.
- **The Cloudflare Access token is persisted at enrollment**, instead of being
  used only for the exchange: without it, every inference started out anonymous
  and received a `302`.
- **An enrolled key can be revoked.** `DELETE /admin/proxy-api-keys/:id`
  answered `404` for any key created by enrollment, even though it kept
  authenticating: offboarding was impossible.
- **An admission policy can be deleted.** Deleting a key left its fair-share
  reservation active, and no endpoint deleted the policy.
  `DELETE /admin/application-policies/:application` fills that gap.
- **A queued turn no longer claims the model is missing.** In `edge-first` mode,
  a wait within the budget answered `503 no_equivalent_model` — false, and
  likely to send someone hunting for a nonexistent mapping bug. It now answers
  `edge_queued` with a `Retry-After` based on the real queue.

### Enrollment

The customer no longer edits their `.env` by hand: `configure --env` writes the
managed block (preserving everything else, in `0600`, idempotently).

The enrollment prompt is generated:

```
npm run hermes:enrollment-prompt -- \
  --code mvenr_… --edge https://host.example.invalid \
  --model <customer's LLM_MODEL> --access-id <id> \
  --access-secret-path <path on the customer's machine> --out prompt.md
```

The Access secret is accepted only as a **path**: it cannot travel in the
prompt. Rendering refuses to emit a document that still contains a placeholder,
and writes `0600` because it carries a live code.

See `docs/hermes-bridge-enrollment-prompt.md` and
`docs/hermes-bridge-cloudflare-access.md`.
