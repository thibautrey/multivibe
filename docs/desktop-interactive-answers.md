# Desktop interactive answers

The macOS chat can answer with text or interactive documents: calculators, comparisons, diagrams, SVG/canvas charts and simulations. Enable **Réponses interactives** in the conversation header, then ask, for example, “Create an interactive bill splitter with adjustable tip and group size.” Existing Host models, Apple models and installed conversation harnesses generate the answer. Model support and output quality vary. The presentation instructions are added to outgoing requests; the original user message remains in device history. Cloud conversations can display compatible documents, but generation instructions are currently added only to Mac conversations.

The native integration adapts [OpenIntelligentUI](https://github.com/CopilotKit/OpenIntelligentUI) at revision `8391a94c1c3939c679e40ddd7bfc08a9ef690e70`: its `generateSandboxedUi` document fields, document assembly, `sendPrompt`/`openLink` bridge and independent-artifact behavior. The upstream MIT notice is bundled in `packaging/macos/resources/OpenIntelligentUI-LICENSE.txt`. This is a native document adapter, without the CopilotKit React runtime, AG-UI stream, Jev router or an additional Python service.

A complete fenced `intelligent-ui` JSON object supplies `title`, `initialHeight`, `placeholderMessages`, `css`, `html`, `jsFunctions`, `jsExpressions`. Only complete valid documents render. Ordinary code fences remain text. Partial interactive fences show a creation indicator; invalid complete blocks remain readable text. Existing message persistence stores the source, so documents survive reopening a conversation without a separate artifact database. Local control state resets when a document is reopened or explicitly reset.

The built-in presentation layer follows the Desktop light or dark appearance and supplies restrained typography, spacing, surfaces, focus rings, form controls, tables and motion preferences. Generated documents can use the `card`, `panel`, `grid`, `stack`, `actions`, `eyebrow`, `metric`, `muted` and `badge` classes. Document CSS is applied after this foundation so a purpose-built answer can still customize its visual language.

Generated code runs in an opaque-origin iframe with `sandbox="allow-scripts"` inside a nonpersistent WebKit view. Content security policies block external requests, libraries, nested frames, form submissions and external images. Use self-contained SVG/canvas and local controls. No provider keys or native tools enter the document. The native handler accepts only main-frame messages from its own wrapper and validates bounded proposals. A follow-up proposes values for review; a separate native button copies them into the composer, where the user sends the next turn. Links similarly require a native review button and HTTPS. Generated content cannot automatically send messages or invoke tools. Documents remain separate snapshots; there is no cross-answer patch API. Arbitrary untrusted JavaScript can still consume resources in its WebKit content process; this is not a general browser or a trusted computation environment.

Validation: `node --test scripts/provider-host/macos-interactive-answers.test.mjs scripts/provider-host/macos-native-chat.test.mjs`, followed by compilation of all macOS Swift sources. The interactive-answer test runs an actual WebKit calculator, verifies restored source parsing, blocks network and storage, checks frame isolation and validates follow-up proposals. This proves native rendering with controlled fixtures, not live model/provider quality or release publication.
