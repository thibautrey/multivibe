# Expansion subscription providers

Reviewed 2026-09-09. The provider descriptors and catalogs live in `src/ai-sdk/expansion-subscriptions/index.ts`. Catalog entries are bounded reviewed snapshots; provider model-list endpoints remain authoritative when accounts are connected.

| Provider | Inference API and catalog source | Subscription / PAYG distinction | Quota support |
|---|---|---|---|
| Chutes.ai | OpenAI-compatible `https://llm.chutes.ai/v1`; [quickstart](https://chutes.ai/docs/getting-started/quickstart) | Subscription windows and PAYG quota are distinct. | The same `cpk_` API key reads `GET https://api.chutes.ai/users/me/subscription_usage`. The fetcher also checks `/users/me/quotas` for additional windows and preserves a successful subscription reading if that optional lookup fails. |
| Venice AI | OpenAI-compatible `https://api.venice.ai/api/v1`; public [`/models`](https://api.venice.ai/api/v1/models) | DIEM/USD API balances are consumable funds, not a hard subscription window. | The API key reads [`GET /billing/balance`](https://docs.venice.ai/api-reference/endpoint/billing/get_balance). MultiVibe reports an absolute balance and never fabricates a percentage. |
| Kilo AI Gateway / Kilo Pass | OpenAI-compatible `https://api.kilo.ai/api/gateway`; public [`/models`](https://api.kilo.ai/api/openrouter/models) | Gateway credit blocks are PAYG; Kilo Pass is a billing-period allowance; Auto Free is separate. Pass utilization is informational because positive PAYG credit can continue serving requests after the Pass allowance is exhausted. | The Kilo token conditionally works with the app's tRPC batch at `https://app.kilo.ai/api/trpc`, using only `user.getCreditBlocks` and `kiloPass.getState`. Payment-method data is not requested. This is a public-app internal API documented by [CodexBar's implementation](https://github.com/steipete/CodexBar/blob/main/Sources/CodexBarCore/Providers/Kilo/KiloUsageFetcher.swift), so failures must remain visible and must not be treated as zero quota. |
| BytePlus Coding Plan | OpenAI-compatible Coding Plan endpoint `https://ark.ap-southeast.bytepluses.com/api/coding/v3`; [official Coding Plan guide](https://docs.byteplus.com/en/docs/ModelArk/1976647) | Coding Plan is a subscription and ordinary ModelArk billing is PAYG. | No official subscription-usage endpoint available to an inference key was found. MultiVibe returns `unsupported` and directs users to the console. No quota or reset is invented. |
| Xiaomi MiMo Token Plan | Three separate OpenAI-compatible descriptors use the fixed China, Europe, and Singapore hosts `https://token-plan-{cn,ams,sgp}.xiaomimimo.com/v1`; [official setup docs](https://github.com/XiaomiMiMo/awesome-mimo-agent/blob/main/docs/qwen_code.md) list the regional form | Token Plan allowance and ordinary `https://api.xiaomimimo.com/v1` PAYG billing are distinct. A regional key is never sent to another region or to the PAYG host. | The only observed usage endpoint, `/api/v1/tokenPlan/usage`, requires the Xiaomi console's HTTP-only session cookie rather than a `tp-` inference key. All three descriptors return `unsupported`; quota remains visible in the MiMo console. |
| Ollama Cloud | OpenAI-compatible `https://ollama.com/v1`; [cloud model directory](https://ollama.com/search?c=cloud) | Free and paid plans can include monthly usage. | [Ollama API keys](https://docs.ollama.com/cloud) can invoke cloud models but do not expose included-plan usage. CodexBar confirms that the meter is scraped from `https://ollama.com/settings` with a browser cookie. MultiVibe does not accept or replay browser cookies, so it returns `unsupported`. |
| Synthetic | OpenAI-compatible `https://api.synthetic.new/openai/v1`; [model docs](https://dev.synthetic.new/docs/api/models) | Subscription quota lanes are distinct from any request-cost accounting. | The same API key reads the official [`GET https://api.synthetic.new/v2/quotas`](https://dev.synthetic.new/docs/synthetic/quotas). Five-hour and weekly token windows are hard model-routing limits; search-hourly is stored as a tool allowance and never drives model routing. |

All quota requests use a fixed reviewed HTTPS origin and `Authorization: Bearer`. HTTP/auth failures reject the refresh, except for the optional Chutes lookup after a successful reading. Unrecognized schemas and credential limitations show `quotaStatus: "unsupported"` with an explanation.

Provider fields explicitly named `percent` are interpreted as percentages without guessing from their numeric magnitude. Thus `0.4` means 0.4%, while ratios are calculated only from documented used/limit values.
