# Conversations from connected environments

Desktop automatically lists supervised Host sessions and native CLI histories from every registered environment, including conversations created outside MultiVibe. Each entry retains its harness and environment. Catalogs refresh while the chat window is open; the selected native or server conversation refreshes independently. An offline environment preserves cached messages and drafts and shows a synchronization error.

Supported native history readers: Hermes, Pi, Codex, Claude Code, OpenCode and Gemini CLI. LibreChat and Open WebUI retain their existing account-bound server synchronization. SSH and bridged containers query the Host inside that environment; an unbridged container never reads the Mac's histories.

Listing and reading never start a harness or acquire an existing CLI process. Replying to a native history uses the adapter's existing isolated fork support (Pi, Codex, Claude Code and OpenCode). Hermes and Gemini histories remain readable; their adapters do not advertise isolated continuation. Server conversations continue in their existing server chat.

Desktop follows native catalog pages automatically: each page scans up to 5,000 file entries or 500 database sessions per harness, with a maximum of 1,001 pages. Unchanged file metadata is cached between polls. Native message reads are bounded to 16 MiB and 20,000 records. Missing entries or failed catalog pages do not delete cached history. Deleting a discovered CLI entry hides it on this Desktop without deleting the original native history. The session inspector remains available for explicit import and raw metadata inspection.

iOS uses the same readers through its paired Host's Personal Relay protocol. While the app is active, it discovers conversations on every paired online instance and registered environment and refreshes the selected history independently. Catalog entries appear before their messages are downloaded. Each entry keeps its instance, environment and harness; server histories additionally retain the connected account identity. Reads never start an adapter. Replies use the existing supervised session, the server conversation, or an isolated CLI fork when supported. Unsupported native continuations are shown as read only. Removing an entry from iOS hides it in that account's local archive without deleting its original history. Cached conversations remain available when a source disappears or goes offline. Both the iOS app and the paired Host need this protocol update; no Cloud route change is required.
