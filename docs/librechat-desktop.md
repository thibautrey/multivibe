# LibreChat in Desktop

Select **LibreChat** in the conversation harness picker. If it is not connected, a sheet asks for the server URL and your LibreChat account. Load the agents, choose one and save. A configured harness is selected directly; **Configure connection…** in its context menu reopens the sheet.

Account sign-in uses `/api/auth/login`. When LibreChat returns a two-factor challenge, Desktop asks for the six-digit authenticator code or a backup code and completes the exchange through `/api/auth/2fa/verify-temp` before loading the agents. The password, verification code, backup code and temporary challenge token are never persisted. The Host privately retains only the resulting user token and refresh cookies and renews an expired local session through `/api/auth/refresh`. An existing user session token remains available for SSO accounts or to resume a browser session; reconnect when that token expires. An agent API key alone cannot read a user's native conversations. Older key-only execution configurations remain usable but must be upgraded to account sign-in for synchronization.

The sidebar synchronizes active and archived conversations from `/api/convos`, including pinned state. The selected conversation reloads its active message branch from `/api/messages/:id`. Desktop polls the catalog every three seconds and selected messages every second while its conversation view is open. Offline or denied reads preserve the cached history and expose a synchronization error. A complete successful catalog reconciles remote deletions, preserving any unsent draft. Server URL and account identity scope every conversation, so changing accounts cannot resume or mutate the former account's chats.

Continuing a conversation uses the native user chat endpoint (`/api/agents/chat` for agents), its original conversation ID and latest parent message. Both direct native SSE and the resumable stream protocol are accepted. The server owns the agent loop, tools and saved messages. New Desktop conversations are saved by LibreChat and appear in the same server history. Renaming, pinning, archiving and deleting a synchronized conversation act on the server; the deletion confirmation explicitly says so.

Credentials are saved with owner-only permissions in the Host's harness-runtime directory and are omitted from read APIs, sessions and events. Endpoints support a reverse-proxy prefix. Redirects are rejected. Use HTTPS outside trusted local networks. Text and text documents are supported. Binary upload, agent editing, manual compaction and acknowledged remote cancellation remain unavailable in this adapter.
